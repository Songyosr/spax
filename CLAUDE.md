# CLAUDE.md — spax

`spax` is an R package for modular raster-based spatial accessibility analysis, implementing the Two-Step Floating Catchment Area (2SFCA) family of methods. Version 0.2.4, MIT licensed.

## Essential Commands

```r
# Development workflow
devtools::load_all()    # Load package in development (source all R/ files)
devtools::document()    # Regenerate NAMESPACE and man/*.Rd from roxygen2 comments
devtools::test()        # Run all testthat tests
devtools::check()       # Full R CMD CHECK (CRAN-level)
devtools::build()       # Build .tar.gz package tarball
```

```r
# Individual test file
testthat::test_file("tests/testthat/test-03-spax_e2sfca.R")
```

## Architecture & Key Patterns

### S3 Class: `spax`

The main result object produced by analysis functions (e.g., `spax_e2sfca()`). Its creation follows a strict three-layer pattern:

```r
.chck_spax(...)    # 1. Validate all inputs (stops on error)
.new_spax(...)     # 2. Construct the S3 object via structure()
.create_spax(...)  # 3. Orchestrates the above (snap=TRUE skips validation)
```

The `spax` object contains:
- `$accessibility` — `SpatRaster` of final accessibility scores
- `$type` — model name string (e.g., `"e2sfca"`)
- `$parameters` — named list of model parameters used
- `$facilities` — optional `data.frame` of facility-level results
- `$iterations` — optional list of per-iteration results
- `$variations` — optional list of Monte Carlo variation results
- `$call` — the original function call

S3 methods are in `R/00-spax_methods.R`: `print.spax()`, `summary.spax()`, `plot.spax()`, `print.summary.spax()`.

### Naming Conventions

| Pattern | Meaning |
|---|---|
| `.dot_prefix()` | Internal (non-exported) function |
| `.assert_*()` | Input validation helper; returns `invisible(TRUE)` or `stop()` |
| `.chck_*()` | Composite input validator for a function/object |
| `.new_*()` | Bare constructor; just calls `structure(..., class = "...")` |
| `.create_*()` | Orchestrates `.chck_*` + `.new_*`; has `snap=` parameter |
| `.help_*()` | Internal computation helper |
| `calc_*()` | Exported calculation function |
| `gather_*()` | Exported data gathering/aggregation function |
| `spread_*()` | Exported data spreading/distribution function |

All exported functions use `snake_case`. File names prefix their numeric order to convey load/dependency order.

### Validation Framework

All user-facing inputs are validated via `.assert_*()` helpers defined in `R/00-utils-validation.R`:

- **Type checks:** `.assert_class()`, `.assert_numeric()`, `.assert_integer()`
- **Value checks:** `.assert_greater()`, `.assert_less()`, `.assert_range()`, `.assert_positive()`, `.assert_proportion()`
- **Dimension checks:** `.assert_length()`, `.assert_lengths_match()`
- **Raster checks:** `.assert_raster()`, `.assert_raster_alignment()`
- **Data frame checks:** `.assert_cols_exist()`
- **NA checks:** `.assert_no_na()`

Error messages always include the parameter name: `stop(sprintf("%s must be ...", name))`.

The `snap = FALSE` parameter on `.create_*()` functions lets internal code skip validation in hot loops for performance.

### Spatial Data

- Primary spatial type: `SpatRaster` from the `terra` package
- `raster` package retained for legacy support
- Multi-layer rasters represent per-facility values (layer names = facility IDs)
- All rasters in a computation must share the same geometry (extent, resolution, CRS) — enforced by `.assert_raster_alignment()`

### Documentation

All exported functions must have roxygen2 comments with at minimum:
- `@description` (or `@describeIn`)
- `@param` for each argument
- `@return`
- `@export` (or `@keywords internal` for non-exported)
- `@examples` with a working example (use `\dontrun{}` when external data/network required)

After any documentation change, run `devtools::document()` to regenerate `man/*.Rd` and `NAMESPACE`. **Never edit these files directly.**

### Testing Conventions

- Test files live in `tests/testthat/` and are named `test-<source-file-name>.R`
- Use `.create_test_data()` (from `R/00-utils-test_data_creators.R`) for reproducible small raster/data.frame fixtures with `set.seed(42)`
- Tests are small (3×3 or 5×5 grids) for fast execution
- testthat edition 3 (`Config/testthat/edition: 3` in DESCRIPTION)

## Code Style

- 2-space indentation (configured in `spax.Rproj`)
- UTF-8 encoding
- Newline at end of file, no trailing whitespace
- Tidyverse style (project uses `styler` — run `styler::style_pkg()` before committing)
- Use `sprintf()` for error messages (not `paste0()`)
- Use `invisible(TRUE)` as the return value of validation functions

## CI/CD

`.github/workflows/pkgdown.yaml` triggers on push to `main`/`master`, PRs, and releases. It builds the pkgdown site and deploys it to the `gh-pages` branch at https://songyosr.github.io/spax/.

There is no automated R CMD CHECK CI. Run `devtools::check()` locally before merging.

## What Not To Do

- **Do not edit** `NAMESPACE` or `man/*.Rd` files manually — they are generated by `devtools::document()`.
- **Do not add** exported functions without roxygen2 docs and a corresponding test file.
- **Do not skip** `.assert_*()` validation for user-facing function arguments.
- **Do not use** `raster` package functions for new code — prefer `terra` equivalents.
- **Do not commit** large binary files to `data/` or `inst/extdata/` without discussion.
